# Aegis Draft

Aegis Draft — учебный помощник для драфтов Dota 2. Пользователь регистрируется,
входит, создаёт собственный драфт, выбирает союзников и противников и получает
объяснимые рекомендации. Каждый выбор сразу сохраняется в PostgreSQL; состав
можно открыть после выхода и нового входа. Статистика матчей не подключена.

## Что уже работает

- регистрация по email и паролю с подтверждением пароля;
- безопасное хранение паролей с помощью `bcrypt`;
- вход и выход из аккаунта;
- защищённая главная страница, доступная только после входа;
- нормализация email и локализованные основные ошибки валидации;
- единый тёмный дизайн входа, регистрации и аккаунта с голубым акцентом;
- фоновый аегис из отдельных символов, которые меняются при движении курсора;
- защищённый UI Kit с демонстрационными карточками, слотами и поиском;
- модели `Hero`, `Draft`, `DraftPick`, учебные seeds и расчёт `Draft#recommendations`;
- список собственных драфтов, создание и редактор двух команд по пять героев;
- поиск по имени и роли, удаление и применение настоящих рекомендаций;
- тесты аккаунта, моделей, полного HTTP-сценария и браузерные Capybara/Selenium-тесты.

UI Kit не читает учебный каталог из базы и не вызывает расчёт рекомендаций.
Выбор карточки в нём не сохраняется. Рабочий сценарий находится в разделе «Мои драфты».

## Локальный запуск

```sh
git clone https://github.com/fezonV/ruby-dota-hero-picker.git
cd ruby-dota-hero-picker
bundle install
bin/rails db:prepare
bin/rails server
```

После запуска приложение доступно по адресу `http://localhost:3000`. Гость с `/`
попадает на экран входа. После регистрации нужно войти отдельно; затем
открывается защищённая главная с основной кнопкой «Мои драфты».

### PowerShell на текущей машине

В этой рабочей копии осталась временная PostgreSQL в `tmp/integration-tools`.
Она не хранится в Git и отсутствует после нового клонирования. Для новой копии
нужно установить PostgreSQL и указать своё подключение через `DATABASE_URL`.

```powershell
Set-Location "C:\Users\mrraz\Desktop\files\repos\ruby-dota-hero-picker"
& .\tmp\integration-tools\pgsql\bin\pg_ctl.exe -D tmp/integration-tools/pgdata -l tmp/integration-tools/postgres.log -o "-h 127.0.0.1 -p 55432" -w start
$env:RAILS_ENV = "development"
$env:DATABASE_URL = "postgresql://postgres@127.0.0.1:55432/aegis_draft_development"
bundle install
ruby bin/rails db:prepare
ruby bin/rails db:seed
ruby bin/rails server -b 127.0.0.1 -p 3000
```

Команду `pg_ctl ... start` выполняйте только если этот экземпляр PostgreSQL ещё
не запущен. Для показа синхронизации откройте `http://127.0.0.1:3000`, войдите,
создайте драфт и откройте его адрес во второй вкладке того же браузера.
Добавьте или удалите героя: обе вкладки должны обновиться автоматически.
Терминал с Rails оставьте открытым; остановка сервера — `Ctrl+C`.

После остановки Rails временную PostgreSQL можно остановить отдельно:

```powershell
& .\tmp\integration-tools\pgsql\bin\pg_ctl.exe -D tmp/integration-tools/pgdata -m fast -w stop
```

Выбранное визуальное направление и поведение фона описаны в [DESIGN.md](DESIGN.md).
В текущей рабочей копии исходная галерея доступна по адресу
`/design-lab/index.html`; каталог `public/design-lab/` исключён из Git и
отсутствует после обычного клонирования репозитория.

Вместо отдельных команд подготовки можно использовать:

```sh
bin/setup
```

Скрипт проверит зависимости, подготовит базу данных и запустит сервер через
`bin/dev`. Для подготовки без запуска сервера используйте `bin/setup --skip-server`.

Чтобы загрузить или обновить учебные записи героев, выполните:

```sh
bin/rails db:seed
```

Seeds содержат 12 героев с вручную заданными характеристиками от 0 до 3.
Повторный запуск обновляет записи по имени. Это не статистика Dota 2.

Официальные портреты всех 12 героев лежат в `public/heroes/` и показываются
в каталоге, составах, рекомендациях и UI Kit. Это исходные PNG Valve 256×144,
уменьшенные в интерфейсе с сохранением пропорций; внешний API для их показа
не нужен. Ссылки на источники — в [public/heroes/README.md](public/heroes/README.md).

### Happy Path и три ответвления

HTTP-сценарии находятся в [DraftFlowTest](test/integration/draft_flow_test.rb).
Запросы проходят через настоящие маршруты, сессии и PostgreSQL, без моков.
В таблице указаны уникальные фрагменты имён тестов для фильтра `--include`.

| Требование | Тест | Ожидаемый результат |
| --- | --- | --- |
| Happy Path | `happy_path` | Регистрация, отдельный вход, создание, рекомендации, замена героя, две команды по пять, повторное открытие и новый вход сохраняют составы и позиции. |
| Гость | `guest_is_sent` | Просмотр, создание и изменение защищены входом; показано требование авторизации, данные сохранены, после входа редактирование работает. |
| Чужой драфт | `another_user_cannot` | Чтение, добавление и удаление дают 404, чужого драфта нет в списке; владелец видит прежний состав и может его менять. |
| Недопустимый выбор: повтор | `duplicate_hero` | Повтор на любой стороне даёт 422; состав не меняется, другой герой добавляется. |
| Недопустимый выбор: шестой герой | `sixth_hero` | Обе стороны ограничены пятью героями; отказ 422 сохраняет состав, удаление освобождает место для нового выбора. |

Нужны доступный PostgreSQL и отдельная тестовая БД. Параметры подключения
можно передать через `DATABASE_URL`; при подготовке БД задайте `RAILS_ENV=test`.
Не используйте базу разработки или рабочие данные для тестов.

```sh
RAILS_ENV=test ruby bin/rails db:prepare
ruby bin/rails test test/integration
ruby bin/rails test test/integration/draft_flow_test.rb --include /happy_path/
ruby bin/rails test test/integration/draft_flow_test.rb --seed 20261127
ruby bin/rails test
ruby bin/rails test:system
```

В PowerShell перед подготовкой БД задайте `$env:RAILS_ENV = "test"`, затем
выполните `ruby bin/rails db:prepare`. Остальные команды запуска одинаковы.
Каждый сценарий можно запустить отдельно, заменив `happy_path` фрагментом из
таблицы. Существующий CI запускает HTTP-тесты и браузерные тесты отдельными заданиями.
Подробности проверок сохранности и изоляции — в [руководстве для защиты](docs/guide-for-defense.md#11-какие-проверки-уже-предусмотрены).

## UI Kit

После входа откройте `/ui-kit` или кнопку «Открыть UI Kit» на главной.
Это живая галерея общих CSS-компонентов: палитра, типографика, кнопки,
поля, состояния ошибок, карточки героев, слоты команды и образец рекомендации.
Поиск и выбор героя работают только внутри демонстрации и не сохраняются.
Страница требует авторизации. Карточки и пример рекомендации заданы прямо в
представлении. Рабочий редактор отдельно использует записи `Hero` из базы.

## Драфты и рекомендации

`Hero` хранит имя, роль и четыре оценки: поддержку, контроль, урон и стойкость.
`Draft` принадлежит пользователю; `DraftPick` задаёт героя, команду и позицию.
Миграция ограничивает допустимые значения, повтор героя и занятое место.
`Draft#recommendations(limit: 5)` исключает выбранных героев, оценивает
оставшихся по дефицитам союзной команды и стойкости противника и возвращает
балл с объяснениями. Это учебная эвристика, не прогноз победы.

Подробные правила и схема описаны в [руководстве для защиты](docs/guide-for-defense.md).
Для объяснения последней доработки подготовлен [пошаговый гайд к защите](docs/draft-defense-guide.md).
Все маршруты драфтов защищены авторизацией. Контроллеры ищут драфт через
`current_user.drafts`, а выбор — через найденный драфт. Чужой или отсутствующий
ресурс возвращает 404. Название ограничено 100 символами. Сервер принимает
только название либо `hero_id` и `team`; владелец и позиция задаются сервером.
`Draft#add_pick` блокирует строку драфта (`with_lock`) на время поиска свободного
места и сохранения. При ошибке ответ — 422, после сохранения — перенаправление 303.
Схема базы и её ограничения сохранены.

### Как пройти сценарий

1. Зарегистрируйся и отдельно войди.
2. Открой «Мои драфты» → «Создать драфт», введи название.
3. В каталоге выбери «Моя команда» или «Противники», найди героя по имени или роли
   и нажми на его карточку. Он займёт первое свободное место. Сторона сохраняется.
4. Прочитай балл и объяснения рекомендации. «Добавить в мою команду» всегда
   добавляет союзника, даже если каталог переключён на противников.
5. Собери пять союзников — появится «Команда собрана». Удали одного: место
   освободится, рекомендации вернутся. После действий видно «Состав сохранён».
6. Вернись в список драфтов, выйди, снова войди и открой сохранённый состав.

### Живое обновление одного драфта

Открой один свой драфт в двух вкладках под одним аккаунтом. Добавь или удали
героя в первой: во второй автоматически обновятся команды, счётчики,
доступность выбора в каталоге и рекомендации. Поисковый запрос и выбранная
сторона каталога остаются своими в каждой вкладке. Страница целиком не перезагружается.

Сервер через Action Cable передаёт Turbo Stream `draft_changed` после коммита
добавления или удаления `DraftPick`. Получившая событие вкладка обновляет блок
редактора через Turbo Frame с актуальными данными и своей стороной каталога.
Ошибки выбора возвращаются с 422 только отправителю; рассылки об изменении нет.
После переподключения блок загружается заново, чтобы получить пропущенные изменения.
Формы также поддерживают обычные HTML-запросы с прежними перенаправлениями.

Подключение использует текущую сессию входа. `DraftUpdatesChannel` проверяет
владельца и соответствие подписанного имени драфту; события отправляются в
отдельный закрытый поток. Выход отключает соединения этой браузерной сессии.
Публикация драфтов, лайки и совместное редактирование разными пользователями
в эту возможность не входят.

В development используется адаптер `async`: Puma и отправитель события должны
работать в одном процессе. В production уже настроен `solid_cable` с отдельной
БД `cable`, которую нужно подготовить вместе с остальными базами приложения.
Рассылка выполняется после коммита в процессе приложения и не требует отдельного worker.

Проверки подписок, HTTP-ответов и реального обновления двух страниц:

```sh
ruby bin/rails test test/channels test/integration/draft_live_updates_test.rb
ruby bin/rails test test/system/live_drafts_test.rb
```

Браузерные тесты используют Chrome/Chromium в headless-режиме и Selenium
Manager для драйвера (первый запуск может потребовать сеть). В CI закреплён
Chrome for Testing `142.0.7444.175`, совместимый с текущим Capybara. Для такого же
локального прогона в PowerShell задай `$env:SE_BROWSER_VERSION = "142.0.7444.175"`.
Если браузер установлен
не в стандартном месте, передай путь через `CHROME_BIN`. При ручном выборе версии
браузера укажи соответствующий ChromeDriver через `SE_CHROMEDRIVER`. Тестовые 12 героев
берутся из fixtures, без seeds и внешних сервисов. Для сохранения снимков страниц:
`VISUAL_QA=1 bin/rails test:system`; PNG появятся в `tmp/visual-qa/`.
